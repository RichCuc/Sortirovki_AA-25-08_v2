# Сравнение сортировок АА-25-08

В `files.txt` перечислены 18 входных файлов. Каждый обрабатывается шестью
алгоритмами: std::sort, Radix, Comb, Heap, Gnome и Shaker. Полный запуск
должен завершиться результатом: 18/18 файлов, 108 сортировок, 0 ошибок.
Каждый результат сравнивается с эталоном std::sort.

## Сборка и запуск

В Visual Studio 2022 откройте `Sortirovki.sln`, выберите Release и x64,
затем нажмите Ctrl+F5. Проект настроен на установленный MSVC 14.44.35207.
Для русских сообщений в стандартной консоли Windows используется CP866.

Нужен C++20: поразрядная сортировка использует std::format.
Запускайте программу из папки с `main.cpp` и `files.txt`.

Clang с поддержкой std::format в стандартной библиотеке:

```sh
clang++ -std=c++20 -O2 *.cpp -o sorts
./sorts
```

MSVC в Developer Command Prompt для x64:

```bat
cl /std:c++20 /O2 /EHsc /utf-8 *.cpp /Fe:sorts.exe
sorts.exe
```

Файлы содержат только числа через пробелы или переводы строк.
Дробная часть отделяется точкой; отдельного числа размера в начале нет.

## Тесты шейкерной сортировки

Три файла содержат один и тот же набор из 10 000 различных чисел
от -8.991954 до 8.999436. Меняется только порядок:

- `shaker_best.txt`: по возрастанию, 0 обменов;
- `shaker_average.txt`: случайная перестановка, seed 15112026 в Python random;
- `shaker_worst.txt`: по убыванию, 49 995 000 обменов.

Уравнены размер и состав данных, поэтому сравнение этих трёх строк
показывает влияние порядка чисел. Файлы `size_100.txt`, `size_1000.txt`
и `size_10000.txt` предназначены для сравнения разных размеров.

В нашей реализации нет флага обменов и досрочного выхода. На каждом
из трёх входов выполняется n(n-1)/2 = 49 995 000 сравнений, поэтому
лучший случай по сравнениям тоже квадратичный. Убывающий вход даёт
максимум соседних обменов, но не обязан иметь наибольшее измеренное
время: на него влияют ветвления и нагрузка процессора. Названия случаев
не являются обещанием конкретного порядка времени.

Полную таблицу на 108 запусков сохраняем. Для обсуждения нашей
сортировки смотрим столбец Shaker, прежде всего три строки shaker_*.
Не следует выбирать только самые быстрые замеры. Для устойчивой оценки
времени используют несколько прогонов и медиану.
